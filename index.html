03 — How It Works

Under the Hood: Five AI Layers

Each layer is a distinct AI capability. They chain together into a continuous assessment loop. Click any layer to see exactly how it works.

01
🔍

DISCOVER

Auto-map services, systems, vendors, people & data dependencies

How Discovery Works

  • NLP reads documents — BCP plans, SOPs, audit reports are parsed to extract service names, ownership, and process flows
  • APM telemetry mining — Real API call patterns from Dynatrace/AppDynamics reveal the actual dependencies (not what people think they are)
  • Contract analysis — NLP reads vendor contracts to automatically identify third-party dependencies and SLA terms
  • Graph construction — Everything feeds into a Neo4j knowledge graph: services → systems → vendors → people → data
95%+ Dependency map accuracy (vs 60% manual)
02
📊

QUANTIFY

Score impact in dollars across 6 dimensions using ML models

How Scoring Works

  • 6 specialized ML models — One per dimension: Financial (XGBoost), Customer (Neural Net), Regulatory (fine-tuned LLM), Reputational (FinBERT sentiment), Systemic (Graph Neural Net), Data (Classifier)
  • Monte Carlo simulation — 100,000 iterations per service to produce loss distributions, not single estimates
  • Cascade analysis — Graph Neural Network predicts how a single failure propagates through the dependency graph
100K Simulations per service for loss quantification
03
🎯

SIMULATE

Generate novel scenarios with GenAI & test on a digital twin

How Simulation Works

  • GenAI scenario engine — Fine-tuned LLM creates novel disruption scenarios from threat intel, past incidents, and our specific tech stack
  • Digital twin — Virtual replica with transaction agents, system agents, and human response agents simulates real behavior
  • Adversarial RL — A reinforcement learning agent is trained to find the worst-case attack paths we haven't considered
  • Plausibility filter — Every generated scenario is scored for realism before testing
10,000+ Novel scenarios generated and tested per quarter
04
🛡️

RESPOND

Optimize recovery sequence & auto-generate runbooks

How Response Works

  • MILP Optimizer — Solves the recovery sequencing problem in seconds: which services to restore first, given dependencies and resource constraints
  • RAG-powered runbooks — LLM retrieves relevant past runbooks, system docs, and vendor guides to produce context-specific recovery steps
  • Dynamic adaptation — Runbooks change based on time of day, available staff, current system state, and active incidents
Seconds To produce optimal recovery plan (vs hours in war room)
05
📋

REPORT

Auto-generate regulatory reports & immutable audit trail

How Reporting Works

  • Template-driven LLM — Maps assessment data to PRA, DORA, OCC report formats automatically
  • Explainability engine — Every score includes plain-English reasoning: "This scored 92 because..."
  • Immutable audit ledger — Every AI decision is logged with input hashes, model versions, confidence scores for full auditability
95% Reduction in regulatory report preparation time

04 — Implementation Approach

How We Build This in 6 Months

We don't build a monolith. We ship working capabilities every 6 weeks using an MVP-first approach. Each sprint delivers a usable product that's better than what we have today.

🎯 The Core Principle: Ship Early, Learn Fast

We don't wait 6 months to see results. Week 6 delivers a working dependency map. Week 12 delivers real-time impact scoring. Each sprint builds on the last and learns from real data.

SPRINT 1

Foundation & Discovery

Weeks 1–6

What We Build

  • Connect data sources: APM telemetry, CMDB, ServiceNow incidents
  • Deploy Neo4j graph database for dependency mapping
  • Build NLP pipeline to parse existing BCP documents
  • Auto-discover service dependencies from real API traffic patterns
  • Produce first auto-generated dependency map

How It Works (Technically)

1
Apache Kafka streams real-time APM data (Dynatrace traces, service call graphs) into a Databricks lakehouse
2
BERTopic NLP models process 10,000+ BCP/SOP documents, extracting service entities, ownership, and process relationships
3
Graph Convolutional Networks analyze API call patterns to infer dependencies that aren't documented — including latent ones from co-failure patterns
4
All discovered relationships populate a Neo4j knowledge graph with node types: Service, App, Database, API, Vendor, Person, DataAsset
✅ Sprint 1 Deliverable Living dependency map with 95%+ accuracy — immediately better than our current 60% self-reported maps
SPRINT 2

Impact Scoring & Cascade Analysis

Weeks 7–12

What We Build

  • Train 6 impact scoring models (Financial, Customer, Regulatory, Reputational, Systemic, Data)
  • Deploy cascade failure predictor on the dependency graph
  • Build Monte Carlo simulation engine for loss quantification
  • Launch real-time risk scoring dashboard
  • Set up automated alerting for impact tolerance breaches

How It Works (Technically)

1
XGBoost regressors trained on historical incident data, revenue per service, SLA penalties, and transaction volumes to predict dollar-loss per hour of disruption
2
Message-Passing Neural Network (MPNN) runs on the Neo4j graph to predict cascade probabilities — "if Node A fails, what's the probability Node B fails within 30 minutes?"
3
Monte Carlo engine runs 100K iterations per service, sampling disruption duration, scope, and timing to produce loss distributions (VaR 95%, VaR 99%, Expected Shortfall)
4
A composite impact score formula combines all 6 dimensions with weights calibrated to our risk appetite: Impact = Σ αd · fd(service, time) · g(duration)
✅ Sprint 2 Deliverable Real-time impact scoring dashboard with dollar-denominated risk for every Important Business Service — with cascade analysis
SPRINT 3

Scenario Simulation & Digital Twin

Weeks 13–18

What We Build

  • Deploy GenAI scenario generation engine (fine-tuned LLM)
  • Build digital twin with agent-based modeling
  • Implement adversarial RL agent for worst-case discovery
  • Integrate with scenario library and plausibility filters
  • Run first automated stress test cycle

How It Works (Technically)

1
Fine-tuned Llama 3 model generates novel disruption scenarios by combining threat intelligence (FS-ISAC, CISA), our tech stack topology, and historical incident patterns
2
Agent-based digital twin (Python/Mesa framework) simulates transaction flows, system behavior under stress, human response times, and vendor SLA adherence
3
Adversarial RL agent (PPO algorithm) is trained to maximize disruption within plausibility constraints — finding attack paths humans never considered
4
A plausibility classifier trained on real banking incidents filters out implausible scenarios, keeping only actionable threats
✅ Sprint 3 Deliverable 10,000+ generated scenarios tested per quarter — including compound and novel threats no human assessor has considered
SPRINT 4

Response Automation & Go-Live

Weeks 19–26

What We Build

  • Deploy recovery optimization engine (MILP solver)
  • Build RAG-powered runbook generator
  • Implement automated regulatory report generation
  • Set up immutable audit trail (Amazon QLDB)
  • SR 11-7 model validation & documentation
  • Production hardening & go-live

How It Works (Technically)

1
Google OR-Tools MILP solver computes optimal recovery sequence in seconds, subject to dependency ordering, resource constraints, and regulatory mandates
2
RAG pipeline (LangChain + vector DB) retrieves relevant past runbooks, system docs, and vendor guides, then an LLM synthesizes context-specific recovery procedures
3
Template-driven reporting maps live assessment data to PRA PS6/21, DORA, and OCC report formats — with LLM-generated executive summaries
4
Challenger models run in parallel for SR 11-7 compliance — automated comparison of primary vs challenger outputs with drift detection (PSI/KS statistics)
✅ Sprint 4 Deliverable Full autonomous assessment system in production — from discovery to response to regulatory reporting — with model governance and audit trail
